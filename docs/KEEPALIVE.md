# 管理器保活

保活对象是定时任务管理器本身。它用于在管理器崩溃、被终止或普通退出后重新打开管理器，不是任务脚本的无限重试功能。

## 使用方式

- 在“设置”中开启管理器保活。首次使用应把程序放在固定目录，再启用保活。
- 关闭主窗口仍然只是隐藏到托盘。保活启用时，普通退出后会重新启动管理器。
- 需要真正退出时，使用托盘中的“关闭保活并退出”，或先在设置中关闭保活，再退出。
- 自动恢复时在后台启动，通过托盘的“显示窗口”打开主界面。

## 工作方式

程序以同一可执行文件的 `--watchdog` 模式启动独立守护进程；守护进程不加载任务配置，也不执行任务。它监测管理器是否存在，并在需要恢复时启动 `--background` 模式的管理器。

管理器退出后首次等待约 3 秒恢复；短时间内反复退出时，等待递增至 10、30、60 秒，最长 60 秒。稳定运行 5 分钟后恢复初始等待。此版本检测进程退出，不检测界面卡死。

当前用户的一个计划任务同时包含登录触发和每分钟触发，用于重新启动守护进程。该任务使用交互用户身份和普通权限，不保存用户密码。管理器和守护进程分别限制单实例，多个启动来源不会同时创建多个调度器。周期任务和守护进程读取同一个保活开关，关闭开关后不得再次恢复管理器。

开关和程序绝对路径保存在 `%APPDATA%\scheduled-task\keepalive.ron`，独立于 `tasks.ron`。计划任务名为 `ScheduledTaskKeepalive-<当前用户 SID>`。移动或替换发布目录后，应从新位置打开程序并重新开启保活，让计划任务指向新路径。删除程序前请先关闭保活。

关闭时先保存关闭状态，再删除计划任务；即使任务清理失败，也会提示错误且停止恢复。开启失败会尝试恢复原配置和计划任务；若回滚也失败，错误提示会说明失败步骤。

如果程序连续崩溃导致无法打开设置，可手动将 `keepalive.ron` 中的 `enabled: true` 改为 `enabled: false`,保留其余内容。守护读取到关闭状态后会退出；仍留在系统中的 `ScheduledTaskKeepalive-<当前用户 SID>` 任务可在 Windows 任务计划程序中删除。

保活适用于当前用户登录后的桌面会话，远程桌面断开但未注销时仍可恢复。注销和关机时暂停恢复，取消注销后继续监测，下一次登录后再根据已保存的开关恢复。它不是 Windows 服务，不保证用户未登录时执行任务。

## 恢复范围

管理器重启后重新读取已保存配置，继续等待后续计划时间。内存中的排队请求不恢复，启动前已经过去的计划时刻不补跑；运行中任务也不自动重新执行。

任务进程由 Windows Job Object 管理，管理器退出或崩溃时会终止这些任务的进程树。因此保活不能保证任务不中断，也不能撤销任务已经完成的文件修改、上传等操作。需要重做中断任务时，请检查实际结果后手动运行。

## 验证边界

开发验证使用临时状态目录和模拟系统操作，不在开发机注册真实登录启动或周期计划任务，不读取真实任务配置执行任务。

发布前应在隔离 Windows 用户中完成以下人工验收：

1. 开启保活后退出管理器，确认只恢复一个后台实例；终止守护进程后确认周期任务能恢复守护。
2. 连续启动多个程序，确认只有一个管理器和一个守护进程，且手动打开能显示已有窗口。
3. 关闭保活并退出，等待超过周期检查间隔，确认不再恢复；注册或注销计划任务失败时确认提示明确且开关状态正确。
4. 注销、取消注销、关机与重新登录，确认退出期间不抢先重启，重新登录后遵守开关状态。
5. 使用无副作用的临时任务确认管理器崩溃后任务进程被清理，恢复后不重跑中断任务、不恢复内存队列。
