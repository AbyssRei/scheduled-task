# 任务行为与开发规格

本文定义 scheduled-task 的运行行为。实现位于 `crates/core`、`crates/app` 和 `crates/keepalive`，行为修改必须同时更新相关测试及本文。

## 配置与身份

任务配置使用 RON，默认文件为 `%APPDATA%\scheduled-task\tasks.ron`，当前 `config_version` 为 2。顶层包含任务列表、主题和全局 `max_parallel`；全局上限必须大于零，默认值为 1。

每个任务以唯一 TaskId 标识，配置不得出现重复 ID。名称仅用于显示，不作为进程登记的键。运行状态不持久化；加载时启用任务为 Ready，禁用任务为 Disabled。

脚本来源支持文件路径或内联内容，类型支持自动识别、Cmd、Windows PowerShell、PowerShell 7、Python、Bash、Sh 和手工命令。Python 可使用系统解释器或 `uv run`；手工命令用 `{script}` 引用脚本路径。内联脚本使用每次执行独立的临时文件，结束后清理。

`timeout: Some(30)` 表示每次执行尝试的超时为 30 分钟，`None` 表示输出读取期间不设置执行超时；重试 `cooldown` 的单位是秒。默认不启用重试；启用重试后，策略默认窗口为 5 行、最大重试次数为 3、冷却时间为 2 秒。

输出管道全部关闭后，执行器单独等待进程收尾：配置超时时重新等待该时长，未配置时最多等待 30 秒，仍未退出则终止进程。因此脚本提前关闭标准输出和标准错误后继续运行时，仍受收尾等待限制。

## 时间调度

调度器每秒读取本地时间。每日及自定义多时间点任务按各自时间点触发；月度任务只在指定日触发，当月不存在该日期时跳过。

FireTracker 以任务、时间点和日期去重，同一任务的同一时间点每天最多触发一次。比较使用当前时间大于等于配置时间，容忍 tick 延迟。启动及重新排程时，已经过去的时间点标记为已处理，不补跑；配置重载保留仍然有效的当日触发标记。过期日期标记定期清理。

超时、冷却和去抖使用单调时间，避免系统墙钟调整影响等待时长。

## 状态机

七种状态为 Disabled（禁用）、Ready（准备就绪）、Queued（排队中）、Running（正在运行）、Retrying（重试中）、Stopping（停止中）、Failed（失败）。Running、Retrying 和 Stopping 属于运行族。

| 当前状态 | 允许转入的其他状态 |
| --- | --- |
| Disabled | Ready |
| Ready | Running、Queued、Disabled |
| Queued | Running、Ready、Disabled |
| Running | Retrying、Stopping、Ready、Failed |
| Retrying | Running、Stopping、Ready、Failed |
| Stopping | Ready |
| Failed | Running、Queued、Ready、Disabled |

同状态转移视为成功。非法转移返回错误并记录警告，不改变状态。正常状态变更必须经状态管理器；编辑任务时可保留已有运行族状态。

执行收尾保留 Failed。运行族先转 Ready，再根据启用状态决定是否转 Disabled；不得从运行族直接跳到 Disabled。用户停止时先进入 Stopping，进程结束后再完成归一化。

任务进程存活监测会核对运行记录；Running 状态下持续未发现活动进程时，经 5 秒去抖后归一化。Retrying 和 Stopping 暂无进程属于正常情况，不按此规则重置。

## 输出与重试

执行器读取标准输出和标准错误，解码后逐行上报。候选重试模式按行拆分，忽略空白行；匹配前压缩连续空白并去除首尾空白，再进行子串匹配。

判定窗口包含当前行和最近的历史行。只有窗口内每行都命中同一个候选模式才触发重试；不同行分别命中不同候选不算连续命中。模式为空时，比较窗口中各行去除常见时间戳和动态耗时、端口数字后的核心内容。

触发重试时终止当前尝试，进入冷却后重新执行；最大重试次数耗尽时保留 Failed。用户停止会中断冷却，避免停止后重新启动进程。关闭调度器拒绝新触发并取消等待队列，已运行任务继续其执行生命周期；管理器进程退出时由 Job Object 清理关联进程。

Windows 使用 Job Object 约束进程树；子进程先挂起创建，加入 Job 后恢复，停止、超时及管理器退出时清理关联进程。

Windows 任务执行统一使用 `CREATE_NO_WINDOW`，默认不显示解释器的控制台窗口，标准输出和标准错误仍通过管道实时回报。该行为覆盖文件脚本、内联脚本及手工命令。脚本主动创建的新终端或图形程序窗口不在此隐藏范围内。

## 并发与等待队列

所有定时与手动触发共用原子准入决策 `admit_locked`，检查启用状态、关闭状态、同任务实例、全局上限及互斥组。

- `parallel`：可与其他任务并行，仍受全局上限和同 TaskId 单实例约束。
- `solo`：同一任务串行，后续触发等待；同 TaskId 单实例约束也适用于其他策略。
- `group("组名")`：同组同时只执行一个任务，组名不得为空白。

每个 TaskId 最多保留一个等待项，队列默认上限 1024。满队列拒绝新触发并记录原因。队列选择最早具备执行条件的任务；同组保持 FIFO，其他组可利用空闲执行槽位。

执行槽覆盖进程运行、重试冷却和停止收尾。任务完成后立即尝试接续等待任务，无需等待下一次 tick。取消令牌在创建进程前、执行轮询及等待退出时检查。

停止会取消该任务等待项并停止当前执行。禁用、删除也取消等待项；关闭调度器取消所有等待并拒绝新触发。运行中禁用任务保留运行族状态，收尾按禁用配置归一化。

提高全局上限立即接续满足条件的任务，降低上限不抢占运行任务。排队任务开始时使用最新配置，运行任务保留本次执行快照。等待队列只在内存中存在。

## 桌面与保活

关闭主窗口隐藏到系统托盘；托盘可显示窗口、普通退出或关闭保活并退出。设置和任务编辑使用主窗口内对话框。主题支持跟随系统、浅色和深色，修改后持久化。

管理器保活默认关闭。启用后，独立 `--watchdog` 进程监测管理器退出，并以 `--background` 恢复。当前用户计划任务提供登录和每分钟的守护恢复入口；管理器与守护分别限制单实例。

恢复等待为 3、10、30、60 秒，连续失败最长等待 60 秒；稳定运行 5 分钟后复位。保活开关独立保存于 `keepalive.ron`，关闭时先持久化，再清理计划任务，所有恢复来源均遵守开关。注销或关机期间停止拉起，只支持交互用户会话。

管理器重启不恢复内存队列、不重跑中断任务、不补跑已经过去的计划时刻。保活不检测界面卡死，也不保证脚本不中断。操作说明和系统验收清单见 [KEEPALIVE.md](KEEPALIVE.md)。

## 日志

控制台默认 INFO，可使用 `RUST_LOG` 调整；文件固定为 DEBUG。日志按天轮转，名称使用 `scheduled_task` 前缀和 `log` 后缀，每个日志目录最多保留 5 个匹配文件。没有单文件字节上限，不能将文件数量限制视为总容量上限。

管理器使用工作目录下的 `logs/`，守护使用程序目录下的 `logs/watchdog/`。图形界面日志视图最多保留 200 行，支持暂停跟随、未读计数和恢复跟随；该限制不改变文件日志内容。

## 验证要求

提交前运行 `cargo test --workspace` 和 `cargo clippy --workspace --all-targets -- -D warnings`，全部通过后交付。执行相关修改还应覆盖真实无副作用脚本、重试耗尽、超时、停止、禁用、并发竞争和队列接续。

保活验证使用临时状态目录和模拟适配层，不注册开发机真实计划任务，不执行真实配置中的任务。跨进程单实例测试使用隔离子进程。真实计划任务、登录、注销、关机和桌面点击验收应在隔离 Windows 用户中进行，测试结果需准确区分静态检查、模拟场景和实际系统操作。
